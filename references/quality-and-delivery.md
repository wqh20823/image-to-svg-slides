# 验证与交付

## 质量门槛

每张图片和每张 SVG 都实际查看。先看全页层级，再放大文字、图标和交叉连线。SVG 必须渲染后检查，不能只看代码。

| 检查项 | 合格标准 |
|---|---|
| 文案 | 人名、数字、单位、符号、事实状态与确认内容一致 |
| 布局 | 构图与阅读顺序保留，模块对齐，边距一致，无裁切重叠 |
| 文字 | 层级清楚，正文真实可编辑，缺字与宽度问题已处理 |
| 图标 | 对称对象规整，圆心一致，线宽与视觉大小协调 |
| 逻辑 | 箭头端点、图例与数据系列正确，连线不穿文字 |
| 编辑 | 文字、容器、图标、连线独立并分组，图片边界如实说明 |
| 保真 | 颜色、间距、位置接近参考，不额外改主题或增删信息 |
| 文件 | XML 有效，引用完整，自包含，正式目录只放最终交付物 |

像素差分只能辅助比较，不能替代人眼判断。抗锯齿与几何规范化会改变像素；低差分也不能证明文字正确或对象可编辑。

## 检查脚本

使用当前 workspace dependencies 工具找到 Python、Node 和包目录，不写死本机用户名与运行时版本。

```text
python check_svg.py slide.svg --font /absolute/regular.ttf --bold-font /absolute/bold.ttf --report /private-build/check.json
```

基础检查仅用标准库。有 --font 时使用 Pillow 度量声明了 data-max-width 的普通文字／多行 tspan。--bold-font 应匹配实际粗体；TTC 可用 --font-index 与 --bold-font-index 选择字体。--require-no-raster 用于纯矢量且没有照片例外的页面。

脚本拒绝无效 XML、重复 ID、悬空引用、外部依赖、正文全图化等明确问题。字体未测量、缺少宽度预算、保留图片、复杂文本布局等需要人工复查。退出码 0 只代表没有确定性错误，不代表视觉验收完成。

```text
node render_svg.mjs slide.svg /private-build/preview.png --node-modules /runtime/node_modules --width 1920
```

渲染使用现有 sharp，保持比例，不自动安装依赖。有可用 Inkscape 等渲染器时也可替代。

## 人工对照

1. 源图与 SVG 预览以相近尺寸比较主视觉、标题、栏宽和安全区。
2. 放大中文笔画、人名、长单位名称、表头、齿轮、圆形、箭头和标志。
3. 读出全部文案并核对来源，确认没有漏项或数字变化。
4. 可用时在目标编辑器确认关键对象可独立选中；未实测只声明源文件结构，不声称已验证 PowerPoint。
5. 修正问题并重渲染受影响页面，不为满足自动风格建议擅改用户版式。

边距、对齐、字宽和缺字可直接修复。内容冲突、关键信息读不清、图表数据缺失等不能靠猜测修复。

## 重试与停止

图像生成先定位问题再重试，不盲目连抽。通常最多两次针对性再生成；仍有缺陷时保留可用结果，明确未解决部分，沿用户已授权的矢量修正路线完成可完成的部分。额外 API、购买、上传、分享或发布不属于重试授权。

SVG 的可修复错误继续处理到满足请求；工具不可用时可换其他本地验证方式，如实说明实测范围。不要把达不到的“全部可编辑”写成完成。

## 干净交付

- 提示词模式：最终逐页提示词，可复制或保存为所需文本文件。
- 图片模式：最终每页图片，用户要求时才另做 PPTX。
- SVG 模式：最终每页 SVG，预览仅用于展示或用户要求时提供。
- 完整流程：逐页提示词、选定图片和 SVG，多页按实际需要打包。

构建脚本、检查报告、调试截图和不采用草稿留在私有目录。不额外写修改说明、路线图或未请求讲稿。

使用已验证的最终路径链接。说明可简洁为“文字、图标与连线可独立编辑，已按模块分组”。照片补充可移动、缩放和替换的边界。SVG 分辨率独立性与生成 PNG 的真实尺寸分别表述。
